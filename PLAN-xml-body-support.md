# XML Body Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make an XML flow behave like a JSON flow for the two nodes that inspect a body — `filter` can match on XML elements and attributes, and `code` can read and rewrite an XML body — and make `hookway validate` reject the body-format mismatches that currently fail silently or at runtime.

**Architecture:** Three independent pieces. (1) `internal/filter` gains an XML path walker beside its existing JSON one, so `source: body` conditions resolve against a `transform.Document`. (2) `internal/flowconfig/node_code.go` stops rejecting XML and instead converts the DOM to a plain-JSON-shaped JS value and back, so goja never sees a Go pointer type. (3) `internal/flowconfig/lint.go` gains a graph walk that pairs each body-consuming node with the `body_format` established on its path, turning three latent runtime failures into config-time errors. No new node types, no new payload types, no changes to `internal/graph`.

**Tech Stack:** Go (stdlib `encoding/xml` only), `invopop/jsonschema` for schema generation, vitest for the UI copy assertions, `make` targets for verification.

**Spec:** None written — this plan was designed directly in conversation from a survey of the existing XML path. The "Context & Design Decisions" section below carries the full design rationale and is the spec; read it before Task 1.

**Depends on:** Nothing. This plan touches no file that `PLAN-builder-templates.md` or `PLAN-http-request-retry.md` touch, and can land before or after either.

## Global Constraints

- **`internal/flowconfig` and everything it imports must stay WASM-safe.** It compiles to `GOOS=js GOARCH=wasm` via `cmd/hookway-wasm` (`Makefile` target `wasm`) for the builder's live validation. `internal/transform` is already stdlib-only and already linked into that build; `internal/filter` must stay that way too. Never import `internal/queue` or anything touching `os`/`net` from these packages.
- **Node option structs are the schema source of truth.** `web/src/graph/nodeSchema.json` is generated by `make node-schema` from `hookway schema --nodes`. Never hand-edit it. `make node-schema-check` fails CI on drift.
- **I6 holds: auth verifies raw bytes, never a re-serialized body.** Every change here happens at or after the `envelope` node, which is already post-auth by port type (`PortVerified` → `PortEnvelope`). No task may move parsing before auth.
- **Filter semantics are fail-closed on a missing value.** A path that does not resolve makes an `exists` condition false and a `not_exists` condition true — that is the existing JSON behavior (`internal/filter/filter.go:325-341`) and XML must match it exactly, not invent a third outcome.
- **No new lint warnings; the three new body-format checks are errors.** They describe configurations that cannot work, not ones that are merely unwise. Use `cfgIssue`, not `cfgWarning` (`internal/flowconfig/config.go:265-275`).
- **Commit convention:** one commit per task, conventional-commit prefixes, and this repo does **not** push by default — leave commits local unless the operator asks otherwise. If your harness supplies a `Co-Authored-By` attribution trailer, append it.
- **Verification commands** (run from repo root): `make test`, `make lint`, `make deadcode`, `make wasm`, `make validate-examples`, `make node-schema-check`, `cd web && npm run test`.

## Context & Design Decisions

Read this before writing code. It is the spec.

**What exists today.** `envelope` accepts `body_format: json|xml|raw` (`internal/flowconfig/nodes.go:69`). With `xml` it parses the verified bytes into a `transform.Document` — a real element tree, not a map — and puts it on `graph.Envelope.Body` (`node_envelope.go:112-120`). `transform` with `kind: xml_prune` rewrites that tree. `http_request` with `body: transformed` re-serializes it and sets `application/xml` (`node_http_request.go:274-290`). `publish` serializes it and base64-encodes it into `raw_body_base64` with `body: null` (`internal/httpapi/flowserver.go:95-117`). Auth is content-type agnostic, so signature verification already works for XML.

So XML flows can already ingest, prune, forward, and publish. What they cannot do is **branch on their own content**.

**Three defects, in descending severity:**

1. **`filter` on an XML body silently never matches.** `resolve` sends `source: body` to `walkBodyPath`, which type-asserts `map[string]any` and returns not-found for anything else (`internal/filter/filter.go:325-341`). An XML body is a `transform.Document`, so the assertion always fails. This was verified by probe, not inferred: with a non-map body, an `exists` condition returns `matched=false` and a `not_exists` condition returns `matched=true`. The config validates clean, the flow runs, and every event takes the `on_no_match` path. A filter meant to drop 1% of traffic drops 100% of it, or a filter meant to keep 99% keeps none — with no error anywhere. This is the reason the plan exists.

2. **`code` rejects XML with a 400 at runtime.** `node_code.go:66-77` returns `"XML bodies are not a script input; use transform xml_prune"`. That message is honest but the restriction is arbitrary from a user's point of view: `xml_prune` is five fixed MISMO-shaped rules (`internal/transform/xml_prune.go:13-27`), so "use xml_prune" is not a general answer. An operator who needs to read one element and set a var has no route at all.

3. **The same class of mismatch exists for `raw` and for the transform kinds, and nothing catches any of it at validate time.** `body_format: raw` sets `event.Body = nil` and never sets `out.Body` (`node_envelope.go:108-111`), so a body filter after a `raw` envelope has exactly defect 1's silent-never-match behavior. And `transform` `kind: field_map`/`changed_fields` on an XML body 400s at runtime, while `kind: xml_prune` on a JSON body 400s at runtime (`node_transform.go:49-56`). All four are decidable from the config alone.

**Seven decisions, and why:**

1. **XML path semantics: dotted local names, root implicit, `@` for attributes.** A JSON filter path `repository.private` addresses a key inside the top-level object. The XML analogue treats the root element as that top-level object — it is the document's wrapper, not data — so path segments address elements *below* the root. `LOAN.Amount` on `<MESSAGE><LOAN><Amount>500</Amount></LOAN></MESSAGE>` resolves to `500`. An `@` prefix reads an attribute: `LOAN.@id`. Local names only; namespace prefixes are ignored for matching, because a vendor is free to change the prefix without changing the document's meaning and a filter should not break when they do.

2. **A leaf resolves to the element's direct text, as a string.** `Element.Text` is already "concatenated direct character data, not descendant text" (`internal/transform/xml_dom.go:22-28`). A string is the right carrier because the existing comparison code already coerces: `toFloat` accepts strings, so `gt`/`lt` work on `<Amount>500</Amount>`, and `kindRegex` requires a string anyway. No new comparison kinds.

3. **Repeated elements: first in document order wins.** `walkBodyPath` already documents "array indexing is not supported" for JSON. XML repetition is the same problem, so it gets the same answer rather than a new indexing syntax. This is a real limitation and Task 5 documents it explicitly; a filter is not the tool for "any of these elements matches".

4. **The walker lives in `internal/filter`, which takes a dependency on `internal/transform`.** The alternative — converting the DOM to a map inside `node_filter.go` and leaving `internal/filter` untouched — was rejected for two reasons: it walks the whole tree on every event even when one path is needed, and it has to invent a map encoding for attributes, which would put path semantics in two places. `internal/transform` imports only stdlib (`bytes`, `encoding/xml`, `fmt`, `io`, `maps`, `strings`), `internal/flowconfig` already imports both packages, and `transform` does not import `filter`, so there is no cycle and no WASM risk. Task 1 Step 6 proves the WASM build still links.

5. **`code` gets an explicit, lossless XML shape — not a convenience mapping.** A "natural" mapping (element name to key, text as value) cannot round-trip attributes, repeated siblings, or mixed content, and a script that reads such a body then returns it would silently destroy parts of the document. So the script sees, and must return, a tagged node shape: `{name, attr, text, children}`. It is verbose to write against, and that is the correct trade: the body is an XML document and the script is editing a tree. The conversion is a pure function pair in a new file, tested round-trip on a document that has all four hard features.

6. **No new config option gates the `code` XML shape.** The node already type-switches on the body (`node_code.go:66-77`); it keeps doing that, and just converts instead of erroring. A `body_mode: json|xml` option was considered and rejected as redundant — the envelope's `body_format` already decides this, and a second knob could disagree with the first. If the script returns a body that is neither the XML shape nor valid JSON, the node 400s with a message naming the expected shape.

7. **The lint guard walks the graph rather than checking node presence.** A flow can have several `envelope` nodes on different branches (after a `switch`), so "does this flow contain an xml envelope" is the wrong question; "what format is established on the path reaching *this* filter" is the right one. `lookupBeforeFilterIssues` (`internal/flowconfig/lint.go:95-146`) already does exactly this shape of walk — root, `graph.ParseEdges`, a stack carrying accumulated state — and Task 3 follows it closely rather than inventing a second traversal idiom.

**What this deliberately does not do.**
- **No general `xml_prune` rule language.** The five hardcoded rules stay. A predicate or XPath DSL is a larger project with its own security surface (an operator-supplied predicate evaluated against payload bytes) and is listed as a follow-up.
- **No XML output from `publish`.** It keeps base64-ing serialized XML into `raw_body_base64`. Changing the published envelope shape is a schema-version question, not a body-support question.
- **No array/repeat indexing in filter paths**, per decision 3.
- **No `transform.field_map` on XML.** Task 3 makes that combination a validate-time error rather than making it work.

Create `internal/filter/xmlpath.go`:

```go
package filter

import (
	"strings"

	"github.com/jasongiroux/hookway/internal/transform"
)

// walkXMLPath resolves a dotted path against an XML document, mirroring
// walkBodyPath's contract for JSON: it returns the leaf value and whether it
// was found, and a value that is absent is simply not found rather than an
// error.
//
// Segments name child elements by local name, starting below the root: the
// root element is the document's wrapper, the way a JSON body's outermost
// object is, so "LOAN.Amount" reads <root><LOAN><Amount>. A segment prefixed
// with "@" reads an attribute of the element addressed so far. Namespace
// prefixes are ignored on both elements and attributes, because a vendor can
// change a prefix without changing what the document means and a filter
// should not break when they do.
//
// Repeated siblings resolve to the first in document order. walkBodyPath has
// the same limitation for JSON arrays; a filter is not the right tool for
// "any of these elements matches".
func walkXMLPath(doc transform.Document, path string) (any, bool) {
	if path == "" || doc.Root == nil {
		return nil, false
	}
	current := doc.Root
	for segment := range strings.SplitSeq(path, ".") {
		if segment == "" {
			return nil, false
		}
		if name, isAttr := strings.CutPrefix(segment, "@"); isAttr {
			// An attribute is terminal: nothing can be addressed below it.
			return attrValue(current, name)
		}
		child := firstChild(current, segment)
		if child == nil {
			return nil, false
		}
		current = child
	}
	// An element that exists resolves to its direct character data. Text is a
	// string so the existing comparisons keep working: toFloat coerces
	// strings, so gt/lt work on <Amount>500</Amount>, and the regex kind
	// requires a string.
	return current.Text, true
}

// firstChild returns the first child element whose local name matches, or nil.
func firstChild(e *transform.Element, name string) *transform.Element {
	for _, child := range e.Children {
		if child != nil && child.Name.Local == name {
			return child
		}
	}
	return nil
}

// attrValue reads an attribute by local name.
func attrValue(e *transform.Element, name string) (any, bool) {
	for _, attr := range e.Attr {
		if attr.Name.Local == name {
			return attr.Value, true
		}
	}
	return nil, false
}
```

```go
package flowconfig

import (
	"encoding/xml"
	"fmt"

	"github.com/jasongiroux/hookway/internal/transform"

// The code node hands scripts an XML body as an explicitly tagged node tree
// rather than a convenience mapping of element names to values. A convenience
// mapping cannot represent an attribute, two siblings with the same name, or
// text sitting beside child elements, so a script that read such a body and
// returned it would silently drop parts of the document. The shape is:
//
//	{
//	  declaration: "<?xml version=\"1.0\"?>",
//	  root: {
//	    name:     "MESSAGE",
//	    attr:     {id: "L1"},
//	    text:     "",
//	    children: [ /* same shape, recursively */ ]
//	  }
//	}
//
// Every value is a string, map[string]any, or []any, so the tree is
// JSON-cloneable and goja can marshal it without seeing a Go pointer type.
func xmlToScript(doc transform.Document) map[string]any {
	return map[string]any{
		"declaration": doc.Declaration,
		"root":        elementToScript(doc.Root),
	}
}

func elementToScript(e *transform.Element) any {
	if e == nil {
		return nil
	}
	attr := make(map[string]any, len(e.Attr))
	for _, a := range e.Attr {
		// Local names only, matching the filter's path semantics: a vendor can
		// change a namespace prefix without changing what the document means.
		attr[a.Name.Local] = a.Value
	}
	children := make([]any, 0, len(e.Children))
	for _, c := range e.Children {
		if converted := elementToScript(c); converted != nil {
			children = append(children, converted)
		}
	}
	return map[string]any{
		"name":     e.Name.Local,
		"ns":       e.Name.Space,
		"attr":     attr,
		"text":     e.Text,
		"children": children,
	}
}

// scriptToXML rebuilds a Document from the shape above. It is strict: a script
// that returns something else gets a message naming the expected shape rather
// than a half-built tree that would serialize into a malformed document.
func scriptToXML(v any) (transform.Document, error) {
	obj, ok := v.(map[string]any)
	if !ok {
		return transform.Document{}, fmt.Errorf("xml body must be an object {declaration, root}, got %T", v)
	}
	rootVal, exists := obj["root"]
	if !exists {
		return transform.Document{}, fmt.Errorf("xml body is missing \"root\"")
	}
	root, err := scriptToElement(rootVal, "root")
	if err != nil {
		return transform.Document{}, err
	}
	if root == nil {
		return transform.Document{}, fmt.Errorf("xml body \"root\" must not be null")
	}
	doc := transform.Document{Root: root}
	if decl, ok := obj["declaration"].(string); ok {
		doc.Declaration = decl
	}
	return doc, nil
}

func scriptToElement(v any, path string) (*transform.Element, error) {
	if v == nil {
		return nil, nil
	}
	obj, ok := v.(map[string]any)
	if !ok {
		return nil, fmt.Errorf("xml %s must be an object {name, attr, text, children}, got %T", path, v)
	}
	nameVal, exists := obj["name"]
	if !exists {
		return nil, fmt.Errorf("xml %s is missing \"name\"", path)
	}
	name, ok := nameVal.(string)
	if !ok || name == "" {
		return nil, fmt.Errorf("xml %s \"name\" must be a non-empty string, got %v", path, nameVal)
	}
	out := &transform.Element{Name: xml.Name{Local: name}}
	if ns, ok := obj["ns"].(string); ok {
		out.Name.Space = ns
	}
	if textVal, exists := obj["text"]; exists && textVal != nil {
		// goja returns float64 for a number; stringify rather than reject so a
		// script can assign a computed value straight to text.
		out.Text = stringify(textVal)
	}
	if attrVal, exists := obj["attr"]; exists && attrVal != nil {
		attrs, ok := attrVal.(map[string]any)
		if !ok {
			return nil, fmt.Errorf("xml %s \"attr\" must be an object, got %T", path, attrVal)
		}
		for k, val := range attrs {
			out.Attr = append(out.Attr, xml.Attr{Name: xml.Name{Local: k}, Value: stringify(val)})
		}
		sortAttrs(out.Attr)
	}
	if kidsVal, exists := obj["children"]; exists && kidsVal != nil {
		kids, ok := kidsVal.([]any)
		if !ok {
			return nil, fmt.Errorf("xml %s \"children\" must be a list, got %T", path, kidsVal)
		}
		for i, kid := range kids {
			child, err := scriptToElement(kid, fmt.Sprintf("%s.children[%d]", path, i))
			if err != nil {
				return nil, err
			}
			if child != nil {
				out.Children = append(out.Children, child)
			}
		}
	}
	return out, nil
}
```

```go
// bodyFormatIssues rejects the combinations where a node inspects a body the
// flow's envelope never produced in a readable form. All of these fail today
// without a config-time error: a body filter after body_format: raw matches
// nothing at all (the envelope leaves Body nil), and a transform whose kind
// does not match the body's shape returns a runtime 400.
//
// It walks forward from the trigger, carrying the format established by the
// last envelope on each path, because a flow may have several envelope nodes
// on different branches of a switch — "does this flow contain an xml
// envelope" is the wrong question. This mirrors lookupBeforeFilterIssues.
func bodyFormatIssues(prefix string, fc graph.FlowConfig) []config.ValidationIssue {
	type nodeInfo struct {
		typ   string
		index int
		cfg   graph.NodeConfig
	}
	info := make(map[string]nodeInfo, len(fc.Nodes))
	root := ""
	for i, node := range fc.Nodes {
		info[node.ID] = nodeInfo{typ: node.Type, index: i, cfg: node}
		if node.Type == "http_trigger" && root == "" {
			root = node.ID
		}
	}
	if root == "" {
		return nil
	}
	edges, _ := graph.ParseEdges(fc.Edges)
	out := map[string][]string{}
	for _, edge := range edges {
		out[edge.From] = append(out[edge.From], edge.To)
	}

	type frame struct {
		id     string
		format string // "", "json", "xml", or "raw"
	}
	var issues []config.ValidationIssue
	seen := map[string]bool{}
	reported := map[string]bool{}
	stack := []frame{{id: root}}
	for len(stack) > 0 {
		cur := stack[len(stack)-1]
		stack = stack[:len(stack)-1]
		key := cur.id + ":" + cur.format
		if seen[key] {
			continue
		}
		seen[key] = true

		node, known := info[cur.id]
		if !known {
			continue
		}
		format := cur.format
		switch node.typ {
		case "envelope":
			format = "json" // the node's own default when body_format is unset
			if opts, err := decodeOptions[EnvelopeOptions](node.cfg); err == nil && opts.BodyFormat != "" {
				format = opts.BodyFormat
			}
		case "filter":
			if !reported[cur.id] {
				if issue, bad := filterBodyFormatIssue(prefix, node.index, cur.id, format, node.cfg); bad {
					reported[cur.id] = true
					issues = append(issues, issue)
				}
			}
		case "transform":
			if !reported[cur.id] {
				if issue, bad := transformBodyFormatIssue(prefix, node.index, cur.id, format, node.cfg); bad {
					reported[cur.id] = true
					issues = append(issues, issue)
				}
			}
		}
		for _, next := range out[cur.id] {
			stack = append(stack, frame{id: next, format: format})
		}
	}
	return issues
}

// filterBodyFormatIssue rejects a body condition that can never resolve. Only
// body_format: raw is unreadable now — json walks dotted keys and xml walks
// dotted element names.
func filterBodyFormatIssue(prefix string, index int, id, format string, nc graph.NodeConfig) (config.ValidationIssue, bool) {
	if format != "raw" {
		return config.ValidationIssue{}, false
	}
	opts, err := decodeOptions[FilterOptions](nc)
	if err != nil {
		return config.ValidationIssue{}, false
	}
	for _, cond := range opts.Conditions {
		if cond.Source == "body" {
			return cfgIssue(
				fmt.Sprintf("%s.nodes[%d].conditions", prefix, index),
				fmt.Sprintf("filter %q reads source: body but reaches an envelope with body_format: raw, which leaves the body empty; every event would take on_no_match", id),
				"use body_format: json or xml, or filter on source: header",
			), true
		}
	}
	return config.ValidationIssue{}, false
}

// transformBodyFormatIssue rejects a transform kind that does not match the
// body's shape. Both mismatches are a runtime 400 in node_transform.go today.
func transformBodyFormatIssue(prefix string, index int, id, format string, nc graph.NodeConfig) (config.ValidationIssue, bool) {
	opts, err := decodeOptions[TransformOptions](nc)
	if err != nil {
		return config.ValidationIssue{}, false
	}
	field := fmt.Sprintf("%s.nodes[%d].kind", prefix, index)
	switch opts.Kind {
	case "xml_prune":
		if format != "xml" {
			return cfgIssue(field,
				fmt.Sprintf("transform %q uses kind: xml_prune but reaches an envelope with body_format: %s; the body is not an XML document and the node would fail at runtime", id, formatName(format)),
				"set the envelope's body_format to xml, or use a json transform kind",
			), true
		}
	case "field_map", "changed_fields":
		if format == "xml" {
			return cfgIssue(field,
				fmt.Sprintf("transform %q uses kind: %s but reaches an envelope with body_format: xml; these kinds walk JSON and the node would fail at runtime", id, opts.Kind),
				"use kind: xml_prune for XML bodies",
			), true
		}
		if format == "raw" {
			return cfgIssue(field,
				fmt.Sprintf("transform %q uses kind: %s but reaches an envelope with body_format: raw, which leaves the body empty", id, opts.Kind),
				"use body_format: json",
			), true
		}
	}
	return config.ValidationIssue{}, false
}

// formatName renders the walked format for a message; an empty format means no
// envelope was reached on this path, which the port types already reject, so it
// only appears in a message when a flow is malformed in some other way too.
func formatName(format string) string {
	if format == "" {
		return "none"
	}
	return format
}
```

````markdown
### XML bodies

An `envelope` with `body_format: xml` parses the verified bytes into an element
tree. The HMAC is always checked against the raw bytes first (I6), so a
document is never parsed before it is trusted.

What understands that tree:

| Node | Behavior |
| --- | --- |
| `filter` | `source: body` paths address element local names below the root, `@name` for an attribute. A leaf compares as a string, so `gt`/`lt` work on numeric text. |
| `code` | The script sees `{declaration, root}` with each element as `{name, ns, attr, text, children}`, and must return the same shape. |
| `transform` | `kind: xml_prune` only. `field_map` and `changed_fields` are JSON-only and are rejected at validate time. |
| `http_request` | `body: transformed` re-serializes the tree and sends `application/xml`. `body: raw` sends the original bytes. |
| `publish` | Serializes the tree and base64-encodes it into the envelope's `raw_body_base64`, with `body: null`. |

Limits worth knowing before you design a flow around it:

- **Namespace prefixes are ignored** for filter paths and in the `code` shape's
  `name`/`attr` keys — a vendor can change a prefix without changing what the
  document means, and a filter should not break when they do. The namespace URI
  is still available to a script as an element's `ns`.
- **Repeated siblings resolve to the first** in document order. A filter cannot
  express "any `LOAN` has an amount over 500"; a `code` node can, by walking
  `children`.
- **`xml_prune` is five fixed rules**, not a rule language:
  `remove_empty_self_closing_elements`, `remove_empty_parents`,
  `remove_hardcoded_only_parties`, `remove_blank_general_partners`,
  `prune_orphaned_relationships`.

`examples/xml.yaml` is a complete flow using all of it.
````

## Follow-ups (not in this plan)

- **A general `xml_prune` rule language.** The five MISMO rules stay hardcoded. A predicate or XPath-ish DSL means evaluating operator-supplied expressions against payload bytes, which needs its own security review (complexity bounds, no backtracking blowup) — a separate project.
- **Repeated-element matching in filters.** "Any `LOAN` with an amount over 500" needs either array indexing or an `any`/`all` quantifier on conditions. Both are filter-language changes affecting JSON equally, so they belong in a filter plan rather than an XML one.
- **XML in the published envelope.** `publish` still base64-encodes serialized XML into `raw_body_base64`. Giving consumers a parsed XML representation changes the envelope contract and is a schema-version decision.
- **`field_map` for XML.** Task 3 makes this a validate-time error. Making it work means defining what a "path" means for writes as well as reads, including creating missing elements — more design than this plan warrants.
